3.2DEFINE

动手前，先答四个问题

Q1
你想做什么？

一句话概括产品 + 目标用户。说不清 = 还没准备好画原型。

Q2
对标谁？

明确说出你想接近哪一类产品。「Notion + Figma + Linear 综合体」= 没对标。

Q3
视觉风格？

引用真实产品 / 风格名 / 关键词。「高级一点」= 没风格。

Q4
差异化是什么？

为什么用户选你不选对标？「AI 加持」= 没差异。

3.3AI CODING

AI Coding：叫法在变，核心不变

Vibe Coding → Agentic Engineering → …… 本质都是：人利用 AI 做出可用产品
🕰️ 三个时代
  • 补全 — 编辑器内单词级建议，"AI as autocomplete"
  • AI IDE — 理解整个项目、多文件改动，"AI as collaborator"
  • Coding Agent — 终端原生 · 长任务 · 自主执行，"AI as autonomous engineer"
🚪 如何入门
  • Build First — 选一个很小的真实需求，今晚跑通第一版
  • Use SOTA — 初学优先用最强模型，先降低失败率
  • Spend Tokens — 先提升使用量；没有体感就没有判断力
3.3WORKFLOW

每个任务的三步工作流

1
Plan ~1 MIN

让 agent 先写计划 + 验收标准，再写代码。不满意就改计划，比改代码便宜。

2
Execute ~3 MIN

同意计划后让它一次写完；边界用 ASCII wireframe / issue 说清楚。

3
Review ~1 MIN

审规格 + 真实跑通，不逐行读代码 —— 浏览器里点一下，发现问题再返工。

3.4DIFFERENTIATION

差异化，藏在最后一公里的细节里

  • 📖 文学时间
    • 近 2000 条语料，按照片 EXIF 的拍摄时刻匹配
    • 不用算法定义「黄昏的气质」，用作家的集体共识 —— 天涯共此时
  • 🎨 色彩引擎
    • 64×64 降采样 → 滤灰黑白 → 频次 ×（饱和度+0.3）→ HSV → 24 桶
    • 难的不是提取颜色，是让推荐色「代表照片的气质」—— 几百张评测图调到第一眼舒服

保持健康的身心

❤️
